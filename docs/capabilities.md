# Capability matrix

These are implemented rules, not a promise that every detected item can be cleaned. All executable rows still require a complete supported operation, user confirmation, intact audit, correct target volume, fresh identity and content checks, and no protection. A detector reporting an item does not override these requirements.

| Detector | Recognition / evidence | Implemented operation | Limits |
| --- | --- | --- | --- |
| npm installed dependencies | Project manifest and npm v2+ lock/shrinkwrap, plus a nonempty `.package-lock.json` installed-package map. Every installed entry must match preserved HTTPS registry URL, integrity, and version metadata and an installed package manifest. | Delete the confirmed dependency tree after complete membership/content validation. | Unknown files outside recorded packages block removal. Local edits inside packages and future registry access remain restoration risks; a lock is not a backup. Empty metadata, local-link layouts, and incomplete provenance are detection-only. |
| pnpm / Yarn / Bun dependencies | Project lock and recognized installed-environment layout, where available. | Detection only. | Complete manager-specific installed membership is not yet proven. Marker names alone never authorize removal. |
| Node build output | Project tool context for `.next`, `.nuxt`, `.turbo`, `coverage`, `dist`, or `build`. | Detection only. | A build script or folder name does not exclude unique files. |
| npm/pnpm/Yarn/Bun stores | Recognized manager cache locations and relevant layout. | Detection only. | No broad cache purge, npx cache destruction, or direct shared-store mutation. A store must be inside the explicitly selected scan scope. |
| Python bytecode | `__pycache__` with only accepted `.pyc`/`.pyo` entries; each maps to preserved adjacent `.py` source. | Delete the confirmed cache tree. | Extra or unmatched contents block execution. |
| Python virtual environment | `pyvenv.cfg`, interpreter layout (`bin` or `Scripts`), a containing Python project, and preserved requirements or uv/Poetry/Pipenv lock input. | Delete the confirmed environment tree. | System-site-packages environments are detection-only. Unpinned requirements are not exact reproducibility. Custom environment files and active use can block execution. |
| pytest | Python project, `CACHEDIR.TAG`, and the strict recognized pytest-cache contents. | Delete the confirmed cache tree. | Unknown contents block execution; last-failed and incremental-test metadata are lost. |
| pip / uv stores | Recognized shared cache layout. | Detection only. | Unique wheels and shared consumers are not exhaustively provable. |
| Maven Java classes | `pom.xml`, `target/classes` or `target/test-classes`, corresponding `src/main/java` or `src/test/java`. | Delete the confirmed class directory. | Only `.class` entries mapping to retained Java source are eligible. Resources, mixed-language output, and unknown files block execution. No whole `target` deletion. |
| Gradle Java classes | Gradle project, `build/classes/java/main` or `build/classes/java/test`, corresponding Java sources. | Delete the confirmed class directory. | Same strict class-only rule. No whole `build` deletion. |
| Maven / Gradle stores | Recognized `.m2/repository` and `.gradle/caches`. | Detection only. | Locally published artifacts may have no remote copy. |
| Runtime managers | Recognized Node/Python/JDK version-manager layouts; identified newest/default/running roles remain protected. | Detection only. | No runtime uninstallation; age does not prove lack of dependents. Unknown dependents remain a limitation. |
| Git | Ordinary local `.git` directory with supported metadata/configuration, stable refs, no unsupported shared/partial/worktree layout, and sufficient temporary free space. Dirty/untracked/ignored worktree classification is unverified. | Linux only: explicit-review `git repack -a -d -n --keep-unreachable` through isolated metadata and descriptor-pinned object directories. Retained refs/HEAD are checked afterwards; the worktree is untouched. macOS/Windows are detection-only. | No object pruning, reflog expiration, server-info update, `git clean`, remote verification/mutation, shallow replacement, or whole-project deletion. Original project config/hooks are not loaded into the repacking process. Requires at least max(64 MiB, 2 × object-store size) free reserve; actual gain is unknown. |
| Docker images | Exact full IDs from a verified local socket/named-pipe daemon; its host storage must be accessible, inside selected roots, and on the target volume. | Explicit-review image removal with `--no-prune`, without force. | Images referenced by any container or having multiple tags are protected. Shared-layer gains are unknown; local images may have no recoverable copy. |
| Docker stopped containers | Same daemon/scope evidence, full container ID, unchanged created/exited state and metadata. | Risky explicit-review removal by exact ID, without force or volume removal. | Writable-layer data is permanently lost. Running, paused, restarting, dead, or unknown states are protected. A stopped container is never recommended automatically. |
| Docker volumes, build cache, virtual storage | Recognized filesystem storage and, where accessible, exact volume inventory. | Detection only. | No broad prune, volume deletion, build-cache cleanup, direct daemon-storage deletion, or Docker Desktop virtual-disk cleanup. Remote endpoints are refused before daemon contact. |
| Large logs / other files | Size and file metadata, with a threshold appropriate to the scan goal. | Explicit-review file deletion, when revalidation and execution gates pass. | No automatic selection. No truncation, content rewriting, or inference that an extension means disposable. Unknown and active files may be protected. |

## Additional safeguards

The engine considers source/manifests activity, available Git state, user configuration, and observed process use. Recent activity defaults to 30 days. The current launch project is protected. Dangerous or sensitive contents and the tool’s own program/runtime/audit are also guarded.

Linux can inspect observable same-user `/proc` cwd, executable, file descriptor, and absolute argument paths. macOS uses trusted system `lsof` for available same-user cwd, executable/text mappings, and open-file paths. Windows uses a native-resolved system PowerShell/CIM query for same-user executable and whole absolute argument paths; cwd and open handles are unavailable. macOS/Windows observations remain partial even when the query succeeds, so they do not enable automatic recommendations. Missing helpers, permissions, or query limits are reported. Manual review does not bypass hard protection or the native execution gate. None of these observations proves the absence of all consumers.

Missing allocation and shared hardlinks reduce confidence in reclaimable bytes. Logical size is not a guaranteed host-space gain. The planner deduplicates overlapping paths and stops after actual target-volume measurements show the goal has been met.

All seven detector families use the same candidate report schema. No external plugin is installed based on project content. See [platform status](platforms.md) for native validation and [audit schema](audit-format.md) for the recorded evidence.
